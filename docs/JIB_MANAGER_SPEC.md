# JIB Manager — المواصفات التنفيذية المستقلة

## القرار المعماري
JIB Manager هو مركز الإدارة والتشغيل المستقل لمنصة JIB. يعمل كتطبيق ويب منفصل عن تطبيق الزبون وتطبيق التاجر وتطبيق المندوب، وله جلسات دخول وصلاحيات إدارة خاصة به. يعاد استخدام تطبيق Next.js الحالي في `apps/admin` لتجنب إنشاء لوحة ثانية مكررة أو كسر إعداد نشر Vercel الحالي؛ الاسم التجاري والواجهة يصبحان JIB Manager، مع بقاء المسار التقني الحالي لتوافق النشر.

لا يحصل JIB Manager على صلاحيات عبر إخفاء عناصر الواجهة. كل قراءة أو تعديل إداري يجب أن يتحقق منه الخادم وRLS أو RPC إداري محمي. لا يوضع مفتاح service-role أو مفاتيح مزودي الخدمات في المتصفح أو مستودع Git.

## الوحدات المطلوبة

1. **مركز القيادة:** مؤشرات حية للطلبات الجديدة، الطلبات قيد التحضير، التوصيلات النشطة، المتاجر النشطة، المنتجات، والمندوبين المعتمدين؛ مع حالة الاتصال ومؤشرات فشل القراءة.
2. **مراقبة الطلبات:** البحث والتصفية حسب الحالة والتاريخ والمتجر والمندوب، تفاصيل الطلب، عناصره، الدفع، العنوان وفق صلاحية المدير، وسجل الأحداث.
3. **الخط الزمني الشامل:** حفظ طابع زمني لكل مرحلة: إنشاء الطلب، قبول/رفض التاجر، بدء التحضير، الجاهزية، إسناد المندوب وقبوله، الاستلام، بدء الطريق، التسليم أو الإلغاء. يعرض للزبون الزمن المنقضي والوقت المتوقع المتبقي. يجب عدم اختلاق ETA؛ يحسب من بيانات فعلية/قواعد تشغيل معلنة ويعرض كتقدير.
4. **إدارة الشركاء:** مراجعة طلبات المتاجر والمندوبين، اعتماد/تعطيل، ومراجعة بيانات المتجر والمنتجات والصور.
5. **إدارة التوصيل:** مناطق الخدمة في الرباط، حدود التغطية، رسوم التوصيل، الحد الأدنى للطلب، أوقات العمل، السعة، التوزيع والإسناد. لا يعتمد أي سعر افتراضي مؤقت في الإنتاج.
6. **المالية:** إجمالي الطلبات، قيمة السلال، رسوم التوصيل، عمولات المنصة، النقد المستحق، التسويات والاسترداد؛ مع سجل تدقيق وعدم تعديل السجلات المالية بصمت.
7. **خدمة الزبائن:** البحث عن طلب أو حساب، ملاحظات الدعم، تصعيد التأخير والشكاوى، دون كشف بيانات غير لازمة.
8. **الإشعارات والاتصالات:** قنوات البريد وSMS وWhatsApp والمكالمات؛ سجل الإرسال وحالة التسليم وإعادة المحاولة ومحددات منع التكرار. العربية والفرنسية للمكالمات. الاتصال عند التحديثات والمشكلات والإصلاحات حسب سياسة التنبيه المعتمدة. الإعداد المحفوظ لا يعني أن مزود الإرسال مربوط؛ يجب التحقق من بيانات الاعتماد والاختبار قبل إعلان التفعيل.
9. **JIB AI Manager:** مراقبة سجلات التشغيل والطلبات والأخطاء، تلخيص الحوادث، اقتراح تشخيص وإصلاح، إعداد تقارير دورية، وتنفيذ إجراءات آمنة محددة. الإجراءات الحساسة (حذف، رد مالي، تغيير رسوم، تعطيل حساب، نشر إصدار، تغيير صلاحيات) تتطلب موافقة بشرية صريحة. كل إجراء آلي يسجل الفاعل والسبب والوقت والنتيجة.
10. **الإعدادات:** اللغات العربية/الفرنسية، العملة MAD، المنطقة الزمنية Africa/Casablanca، قنوات التنبيه، سياسة التصعيد، مزودو الخرائط والدفع والرسائل، وإدارة مفاتيح الخدمات عبر أسرار بيئة النشر.

## دورة الطلب المعتمدة
pending → accepted أو rejected → preparing → ready_for_pickup → courier assigned/accepted → picked_up → delivering → delivered. حالات cancelled والاستثناءات لها سبب واضح. كل انتقال ذري ومصرح به عبر RPC موثوق، ويسجل في order_events. لا يسمح للعميل أو المتجر أو المندوب بتغيير حالة خارج انتقالات دوره.

## مبادئ الأمان والموثوقية
- جلسات إدارة محمية والتحقق من الدور في الخادم.
- RLS على كل جدول، وأقل صلاحية لازمة لكل دور.
- عدم كشف عنوان الزبون أو هاتفه إلا للمشارك المصرح وفي المرحلة المناسبة.
- عمليات الإدارة الحساسة عبر RPC يتحقق من `is_jib_admin()` وتسجل تدقيقاً.
- عدم تضمين مفاتيح سرية في تطبيقات Flutter أو Next.js client.
- حدود معدل، تحقق مدخلات، منع التكرار، ومعالجة آمنة للأخطاء.
- نسخ احتياطي واختبار استعادة قبل الإطلاق العام.
- لا توصف ميزة بأنها مكتملة إلا بعد اختبار آلي ويدوي وتحقق من بيئة فعلية.

## ما هو قائم وما لم يكتمل
- قائم: تطبيق Next.js مستقل ضمن `apps/admin`، مصادقة Supabase SSR، تحقق دور admin في الخادم، ولوحات قراءة للطلبات والمتاجر والمنتجات والمستخدمين، وبعض إجراءات اعتماد المتاجر والمندوبين.
- قائم: مشروع Supabase وRLS ومخطط الطلبات وسجل الأحداث وإجراءات تسجيل التاجر والمندوب وبعض عمليات المندوب.
- غير مكتمل: خط زمني تفصيلي لكل مرحلة، إسناد آمن متكامل من الإدارة، ETA، لوحة إشعارات قابلة للتحقق، مزود مكالمات/SMS/WhatsApp، الخرائط الحية، إدارة المناطق والرسوم، التقارير المالية، سجل تدقيق إداري شامل، وربط نموذج ذكاء اصطناعي بمفاتيح ومزود محدد.
- لا توجد متاجر أو منتجات أو طلبات إنتاجية مؤكدة في آخر مراجعة؛ يلزم إدخال شركاء تجريبيين بموافقتهم قبل اختبار التشغيل الواقعي.

## خطة التحقق
1. CI: بناء Next.js، ESLint/TypeScript، وتحليل واختبارات Flutter الثلاثة.
2. أمان: اختبار مستخدم غير إداري، تاجر، مندوب، وزبون ضد كل مسارات الإدارة وRPC.
3. رحلة كاملة: طلب حقيقي من الزبون، قبول التاجر، إسناد مندوب، استلام، تسليم، والتحقق من سجل الأحداث والوقت.
4. اتصالات: رسائل تجريبية لكل قناة مع التحقق من حالة التسليم وعدم تكرار التنبيه.
5. تشغيل: اختبار الضغط والأخطاء والنسخ الاحتياطي واستعادة البيانات.
6. إصدار: بناء APK تجريبي وتوقيع إصدار الإنتاج بعد إعداد مفاتيح التوقيع خارج Git.
