# JIB — مواصفات المنتج

## الرؤية
منصة توصيل محلية موثوقة وسهلة الاستخدام في الرباط، قابلة للتوسع لاحقاً إلى مدن مغربية أخرى.

## المستخدمون والأدوار
1. الزبون: اكتشاف المتاجر والمنتجات، إدارة العنوان والسلة، إنشاء الطلب، الدفع، تتبع الحالة والتقييم.
2. السائق: استقبال عروض التوصيل، قبول المهمة، تأكيد الاستلام والتسليم، ومتابعة الأرباح.
3. التاجر: إدارة المتجر والمنتجات والأسعار والتوفر، واستقبال الطلبات وتحديث حالتها.
4. الإدارة: إدارة الحسابات والمتاجر والسائقين والطلبات والمناطق والعمولات والعروض ومراقبة الأداء.

## نطاق MVP
- مدينة الإطلاق: الرباط.
- المنصة متعددة المتاجر والفئات، وليست مقتصرة على المطاعم أو الأطباق المغربية.
- الفئات التجارية تشمل المطاعم والوجبات السريعة والمخابز والمشروبات والبقالة والخضر والفواكه واللحوم والأسماك والمنتجات المنزلية والعناية الشخصية والإلكترونيات والأزياء والتجميل والزهور والهدايا والألعاب والكتب والقرطاسية ومستلزمات الحيوانات والرياضة والسيارات والصيدليات والسلع العامة.
- يجب أن تدعم بنية الكتالوج أسماء المنتجات والعلامات التجارية وSKU والباركود والخيارات والخصائص والصور والتوفر والأسعار.
- المتاجر الفردية والسلاسل التجارية (مثل McDonald's وBurger King وKFC وغيرها) تُسجل كمتاجر مستقلة ذات فروع وهوية تجارية وإمكانية ربط تكامل خاص بها.
- اللغات: العربية والفرنسية في الواجهة الأولى.
- العملة: الدرهم المغربي (MAD).
- الدفع الأولي: نقداً عند التسليم.
- الطلب: سلة، عنوان توصيل، ملاحظات، رسوم توصيل واضحة، وحالات طلب متتابعة.
- التتبع: حالات الطلب أولاً؛ التتبع الحي بعد إعداد خدمة الموقع والصلاحيات.

## تدفق الطلب
1. يختار الزبون المتجر والمنتجات.
2. يتحقق النظام من توفر المنتجات ومنطقة التوصيل.
3. ينشئ الطلب بحالة pending.
4. يؤكد التاجر الطلب أو يرفضه مع سبب.
5. يُسند الطلب إلى سائق متاح.
6. تتتابع الحالات: accepted, preparing, ready_for_pickup, picked_up, delivering, delivered.
7. يُسجل الدفع النقدي ويُتاح التقييم بعد التسليم.

## مبادئ أساسية
- لا يُعرض متجر على أنه متاح إذا كان خارج منطقة الخدمة أو مغلقاً.
- الأسعار والرسوم والمجموع تُحسب وتُتحقق على الخادم.
- لا يستطيع أي دور قراءة أو تعديل بيانات دور آخر إلا بصلاحية واضحة.
- كل انتقال مهم في حالة الطلب يُسجل في سجل أحداث.
- حماية بيانات الزبائن ومواقعهم أولوية.


## سلاسل المطاعم والمتاجر والشركاء
- يجب أن يدعم JIB تسجيل سلسلة تجارية كعلامة/حساب متجر رئيسي، وربط فروعها ومناطق خدمتها وقوائمها وأسعارها وتوفرها.
- وسائل التشغيل المدعومة تصميمياً: إدارة يدوية من لوحة التاجر، استيراد كتالوج بموافقة الشريك، تكامل API رسمي، أو تكامل POS عند توفير الشريك وثائقه وبيانات الاعتماد.
- لا يُعلن عن سلسلة مثل McDonald's كشريك متصل ولا تُعرض قوائمها/أسعارها على أنها رسمية قبل موافقة الشريك أو الحصول على مصدر بيانات مرخص ومحدّث.
- لا تُخزن مفاتيح API أو كلمات المرور في حقول JSON العامة أو قاعدة بيانات الكتالوج؛ تُدار الأسرار في مخزن أسرار آمن عند توفر التكامل.
- عند غياب API رسمي، يمكن بدء onboarding يدوياً بموافقة المتجر، ثم مراجعة القائمة والأسعار والتوفر من صاحب الصلاحية.
- صور العلامات التجارية والتغليف والشعارات تُستخدم فقط من مواد يوفرها الشريك أو من مصادر تسمح تراخيصها بالاستخدام التجاري؛ لا تُختلق شعارات أو صور منتجات رسمية.

## الذكاء الاصطناعي وكتالوج المنتجات
- محرك الصور موحد لكل المنتجات التجارية، وليس للطعام فقط.
- يصنف المنتج إلى فئة مناسبة ويكتب تعليمات تصوير خاصة بها، مع الحفاظ على اسم المنتج ووصف التاجر واللون والحجم والكمية والعبوة والخصائص.
- تُعطى الأولوية لصور مرجعية يملك التاجر أو الشريك حقوق استخدامها. لا يخترع النموذج شعاراً أو نص عبوة أو مواصفات غير مذكورة.
- صور الطعام تُستخدم لها ملفات مرجعية للأطباق، ومنها الأطباق المغربية، مع عدم حصر الكتالوج فيها.
- كل الصور المولدة تبقى مسودات حتى مراجعتها واعتمادها بشرياً.
- سياسة التنفيذ: استخدام المصادر المفتوحة والخطط المجانية فقط؛ لا ترقية مدفوعة أو مزود مدفوع دون موافقة صريحة.
